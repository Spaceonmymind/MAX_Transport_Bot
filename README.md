# Транспорт Курганской области

Самостоятельный информационный чат-бот MAX для Департамента экономического развития Курганской области: [@kurgan_transport_bot](https://max.ru/kurgan_transport_bot). Он показывает интерактивное меню, отвечает на `/start` и `/menu`, обрабатывает callback-кнопки и возвращает пользователя в меню из любого раздела.

## Архитектура

```text
app/                 FastAPI, обработчики, клиент MAX API, меню и логирование
data/menu.json       Все пользовательские тексты, пункты меню и ссылки
scripts/             Одноразовая регистрация webhook
nginx/               Отдельный пример server block
tests/               Автоматические тесты без реальных вызовов MAX
```

`data/menu.json` проверяется Pydantic при старте. Меню допускает подменю, ответы, ссылки и короткие стабильные callback payload (`go:<id>`, `nav:back:<id>`, `nav:main`). Тексты редактируются только в JSON; Python-код менять не нужно.

MAX API настроен по актуальной документации: базовый адрес `https://platform-api2.max.ru`, сообщения через `POST /messages`, callback-ответы через `POST /answers`, а подписка webhook — через `POST /subscriptions`. Входящий webhook проверяется сравнением `X-Max-Bot-Api-Secret` с `MAX_WEBHOOK_SECRET`. Повтор одного update_id не обрабатывается повторно в пределах жизни процесса.

## Настройка и локальный запуск

```sh
cp .env.example .env
# заполните MAX_BOT_TOKEN и MAX_WEBHOOK_SECRET
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Проверка: `curl http://127.0.0.1:8000/health` должна вернуть `{"status":"ok"}`. Запуск без корректных обязательных переменных или с некорректным JSON завершится понятной ошибкой до приёма webhook.

## Docker и развёртывание

Все команды выполняйте из директории этого проекта. Проект не использует host network, Docker socket, privileged-режим или внешние порты по умолчанию. Контейнер запускается непривилегированным пользователем, перезапускается с `unless-stopped` и ограничивает Docker-логи.

```sh
cp .env.example .env
# заполните .env
chmod +x deploy.sh
./deploy.sh
docker compose up -d --build
docker compose ps
docker compose logs -f
docker compose restart
docker compose down
```

`deploy.sh` действует только на текущий Compose-проект: он не вызывает `docker compose down`, `docker system prune` и не изменяет чужие контейнеры, сети, тома или конфигурацию Nginx. Перед публикацией порта проверьте свободные порты, например `ss -ltn`. Если Nginx установлен на хосте, раскомментируйте в `compose.yaml` публикацию вида `127.0.0.1:8017:8000`, выбрав свободный порт.

Для обновления выполните в этой же директории `./deploy.sh`: будут пересобраны и перезапущены только сервис и контейнер `max-transport-bot`.

## Nginx, DNS, HTTPS и webhook

1. Создайте DNS-запись выбранного домена или поддомена на IP сервера. Не предполагается, что какой-либо конкретный домен уже указывает на сервер.
2. Выберите свободный локальный порт, включите его публикацию на `127.0.0.1` в `compose.yaml` и запустите проект.
3. Скопируйте [nginx/max-transport-bot.conf.example](nginx/max-transport-bot.conf.example) как отдельный сайт Nginx, замените домен, пути сертификата и порт. Не перезаписывайте существующие server block.
4. Выпустите сертификат доверенного центра для этого домена (например, Certbot), проверьте `nginx -t`, затем выполните `systemctl reload nginx`.
5. Укажите в `.env` `PUBLIC_BASE_URL=https://ваш-домен` и выполните `python scripts/register_webhook.py` один раз.

MAX требует HTTPS, порт 443 и сертификат доверенного центра; URL webhook складывается из `PUBLIC_BASE_URL` и `WEBHOOK_PATH`. Регистрация намеренно не запускается при старте контейнера. После неё проверьте `/health`, отправьте `/start` боту и посмотрите `docker compose logs -f`.

## Тестирование

```sh
python -m pytest -q
python -m json.tool data/menu.json >/dev/null
docker compose config
```

Тесты мокируют MAX API и покрывают загрузку JSON, разделы и навигацию, `/start`, `/menu`, неизвестный текст и callback, webhook secret и повторную доставку. Реальные сообщения не отправляются.

## Замечания к исходному документу

- В файле присутствует ссылка-пример `https://max.ru/mintransrussia_bot`, не относящаяся к заданному боту; она не включена в пользовательское меню.
- В пункте о льготах Кургана в оригинале отсутствует пробел между `№ 183` и открывающей кавычкой. Формулировка сохранена без исправления.
- В исходном документе нет ссылки на сам нормативный акт по льготам в Кургане или Шадринске, поэтому кнопки-ссылки для этих двух ответов не добавлены.
